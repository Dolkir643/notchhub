# NotchHub

Хаб в чёлке MacBook: музыка, полка для файлов, история буфера, заготовки,
календарь и переводчик — всё под вырезом камеры, без иконки в Dock.

## Сборка

```bash
./Scripts/build.sh     # собрать NotchHub.app в build/
./Scripts/run.sh       # пересобрать и перезапустить из build/
./Scripts/install.sh   # собрать и поставить в /Applications (рабочая установка)
./Scripts/dmg.sh       # универсальный образ build/NotchHub-<версия>.dmg для раздачи
```

Приложение живёт в `/Applications/NotchHub.app`. После правок кода обновляй его
через `install.sh` — `run.sh` перезапускает копию из `build/`, и тогда в системе
окажутся две разные.

Нужен Xcode (скрипт сам подставляет `DEVELOPER_DIR=/Applications/Xcode.app/...`,
потому что `xcode-select` в системе указывает на Command Line Tools) и `cmake`
для сборки `MediaRemoteAdapter.framework`.

Результат — `build/NotchHub.app`. Приложение можно перетащить в `/Applications`.

## Выход из приложения

Иконки в Dock нет: чтобы выйти, наведи курсор на чёлку → вкладка «Настройки» → «Выйти».
Или `pkill -x NotchHub`.

## Разрешения

| Что | Когда спрашивается | Зачем |
|-----|--------------------|-------|
| Календарь (полный доступ) | по кнопке во вкладке «Календарь» | показывать ближайшие встречи |
| Automation (Музыка/Spotify) | только если сломан MediaRemote | резервное управление плеером |

**Про раздачу.** `dmg.sh` собирает приложение **универсальным** (arm64 + x86_64)
и кладёт в образ вместе с ярлыком «Программы» и запиской по установке. Две вещи,
на которых легко обжечься:

- на Apple Silicon системный `perl` запускается как arm64 и x86-фреймворк адаптера
  не загрузит — музыка отвалится молча, поэтому обе архитектуры обязательны;
- cmake без `CMAKE_OSX_DEPLOYMENT_TARGET` берёт версию хозяйской системы: собранный
  на macOS 26 фреймворк на маке с 14–15 не загрузится, хотя приложение заявляет 14.0.
  Обе цели зафиксированы в `build.sh`, проверять так:
  `vtool -arch arm64 -show-build <бинарь> | grep minos`.

Образ **не нотаризован** (нет платного аккаунта разработчика), поэтому на чужом маке
Gatekeeper его отклонит — первый запуск через правый клик → «Открыть». Это написано
в записке внутри образа.

**Про автозапуск.** `SMAppService.mainApp.status` до первой регистрации отдаёт
`.notFound` — это не отказ, а «записи ещё нет»: `register()` из этого состояния
проходит, и статус становится `.enabled`. Проверено живьём; ad-hoc подпись
регистрации не мешает, и она переживает пересборку с переустановкой.

Подпись ad-hoc (сертификата разработчика на машине нет), поэтому **после каждой
пересборки система считает приложение новым** и выданные разрешения придётся
подтверждать заново.

## Устройство

```
Sources/NotchHub/
  App/        точка входа, делегат, глобальное состояние, автозапуск
  Window/     NSPanel поверх меню-бара, геометрия чёлки, форма с анимируемыми углами
  UI/         корневое вью, полная панель, элементы плеера, вкладки
  Services/   музыка, полка, буфер, заготовки, календарь, переводчик
  Support/    настройки, пути, логи, форматирование, хаптика
Vendor/mediaremote-adapter/   исходник адаптера MediaRemote (ungive), собирается cmake
```

Разделение обязанностей и правила модулей — в [CONTRACT.md](CONTRACT.md).

## Как это работает

- Окно — `NSPanel` без рамки, `nonactivatingPanel`, уровень `.mainMenu + 3`,
  `canJoinAllSpaces` + `fullScreenAuxiliary`: видно поверх строки меню и фуллскрина.
  Прозрачные пиксели пропускают клики в приложения под панелью.
- Состояний ровно два: пустой чёрный островок и раскрытая панель. Раскрытие —
  одна пружина: размер, скругления и размытие фона едут одним движением, без
  промежуточной карточки. Задержка перед раскрытием — 0,12 с, в настройках
  ставится вплоть до «сразу».
- На свёрнутом островке не рисуется ничего: ни бейджей полки, ни подтверждений.
- Клавиатуру панель принимает только в раскрытом виде (`canBecomeKey` включается
  на время), поэтому в свёрнутом состоянии она физически не может украсть фокус.
- На экране без выреза островок рисуется как карточка с одинаковыми скруглениями
  сверху и снизу (системной «непрерывной» кривой). Обратные плечи включаются
  только там, где вырез настоящий, — иначе вокруг камеры остаются светлые щели.
- Иконка «Музыки» — наушники, а не нотка: залитая нотка среди контурных соседей
  читается плотнее и лезет в глаза, хотя закрашивает меньше всех.
- Чтобы разглядывать панель, не удерживая курсор, есть отладочный запуск —
  панель залипает раскрытой на нужной вкладке:
  `NOTCHHUB_DEMO=settings ./build/NotchHub.app/Contents/MacOS/NotchHub`
- Верхняя кромка зоны наведения включена в неё намеренно: курсор, упёртый в самый
  верх экрана, имеет y ровно `screen.frame.maxY`, а `CGRect.contains` свою верхнюю
  кромку своей не считает — островок не раскрывался ровно там, куда мышь приходит
  естественнее всего. Переходы зоны пишутся в журнал на уровне debug:
  `log stream --predicate 'subsystem == "name.notchhub.NotchHub"' --level debug`.
- Наведение отслеживается глобальным монитором `NSEvent` плюс страховочным
  опросом 5 раз в секунду: обычный `.onHover` в неактивном приложении-агенте
  срабатывает не всегда.
- Плеер по умолчанию — **Яндекс Музыка**: вкладка «Музыка» работает как пульт к ней.
  Отдельного кода приложение не требует — оно на Electron, а Chromium внутри отдаёт
  трек системе через Media Session, то есть тем же потоком MediaRemote, что и все
  остальные. Когда ничего не играет, вкладка предлагает открыть Яндекс Музыку.
  Что именно отдаёт система — покажет `./Scripts/now-playing.sh`.
- Now Playing читается через `/usr/bin/perl` + `MediaRemoteAdapter.framework`:
  прямой доступ к MediaRemote закрыт для сторонних приложений с macOS 15.4,
  а системный perl остался допущенным. Chrome и YouTube попадают туда сами
  через Media Session API.
- Поток `perl` переживает смерть приложения (Force Quit, падение), поэтому
  NotchHub ловит SIGTERM и выходит по-человечески, а на старте подметает
  осиротевшие потоки прошлых запусков — иначе они копятся клиентами MediaRemote.
- На экранах без выреза рисуется псевдо-чёлка высотой в строку меню — на Intel-маках
  и внешних мониторах это основной режим.

## Что проверено вживую

На этой машине (MacBook Pro 16,2, Intel, macOS 26.5.2, **чёлки нет** — работает
псевдо-чёлка) проверено запуском собранного `.app`:

- псевдо-чёлка рисуется по центру строки меню, наведение раскрывает панель пружиной;
- панель не забирает фокус: `frontmostApplication` при раскрытии не меняется;
- все семь вкладок отрисованы и влезают в панель целиком;
- адаптер MediaRemote внутри бандла проходит `test` (exit 0), в подвале настроек
  честно написано «музыка: MediaRemote»;
- буфер: кириллица, ссылки, порядок, счётчик на иконке вкладки;
- **приёмка по приватности**: запись с меткой `org.nspasteboard.ConcealedType`
  (как у 1Password) в историю не попадает;
- полка: свежий снимок ⌘⇧4 сам появляется на полке с превью и пометкой «снимок».

## Что нужно проверить руками

Это требует твоих рук — либо системного разрешения, либо жеста мышью:

1. **Яндекс Музыка.** Включи любой трек в приложении «Яндекс Музыка». Наведи курсор
   на островок — панель раскроется на «Музыке»: большая обложка, времена, перемотка,
   в шапке — иконка и имя источника. Пауза/следующий/предыдущий должны управлять
   приложением. Обложка при перемотке мигать не должна.
   Если карточка не появилась — `./Scripts/now-playing.sh`: в `bundleIdentifier`
   должно быть `ru.yandex.desktop.music`. Это единственное, что я не смог проверить
   сам: без воспроизведения MediaRemote молчит, а запускать музыку в твоё
   отсутствие я не стал.
2. **Перетаскивание файла с полки наружу** — в Telegram, Finder или Claude Code.
   Единственное, что нельзя было проверить программно.
3. **Календарь.** Вкладка «Календарь» → «Разрешить доступ» (macOS спросит один раз).
4. **Переводчик.** Набери текст в верхнем поле; направление определяется само по
   кириллице. Первый перевод может попросить докачать языковой пакет.
5. **Автозапуск** уже включён (приложение стоит в `/Applications`). Выключается
   там же — «Настройки» → «Запускать при входе», или в Системных настройках →
   Основные → Объекты входа.
